# n8n: Karyakarta document pipeline

`karyakarta_document_pipeline.n8n.json` is the workflow (generated by `build_workflow.py`; edit the script, not the JSON).

```
Documents uploaded (webhook POST /webhook/karyakarta-documents  {case_id, doc_ids, dataset})
 → Settings (backend_url = http://host.docker.internal:8765)
 → Split out documents → Loop over documents (one at a time)
     → Extract + check (Sarvam via backend)      POST /api/documents/{id}/extract      timeout 180 s
         ↳ on error: Mark extraction failed      POST /api/documents/{id}/status
     → Get memory summary                        GET  /api/documents/{id}/memory-summary
     → Cognee: store document                    native Cognee node, Memory > Remember (summary text, unique file name prefix, background)
     → Report memory result                      POST /api/documents/{id}/memory/result  (stored | failed)
 → (after all documents, once)
   Mark graph building → Cognee: build knowledge graph (native Cognify) → Report graph result
   → Cross-check documents (POST /api/cases/{id}/cross-check) → Issues found?
       ↳ yes: Needs attention: voice chase (placeholder)    ↳ no: Ready for KAM review
```

Every step that can fail continues (it never stops the run): extraction errors go to the error branch; Cognee errors
are reported to the backend as `memory_status: failed` / `graph_status: failed`. Sarvam is only ever called by the
backend. Cognee is called by the native nodes using the n8n credential **Cognee Cloud (Karyakarta)**.

## One-time setup (already done on this machine)

Paths below are inside the container. From Git Bash, prefix `docker exec` commands with `MSYS_NO_PATHCONV=1`,
or Git Bash rewrites `/tmp/...` into a Windows path.

1. Community node: `docker exec -u node n8n sh -c "cd ~/.n8n/nodes && npm install --legacy-peer-deps n8n-nodes-cognee@0.7.0"`,
   then `docker restart n8n`. (Or in the UI: Settings → Community Nodes → install `n8n-nodes-cognee`.)
2. Credential: in the UI, Credentials → New → **Cognee API**: Base URL = `COGNEE_BASE_URL`, API key = `COGNEE_API_KEY`.
   Name it `Cognee Cloud (Karyakarta)` (the workflow references id `kkCogneeCloud01`; if you create it in the UI,
   re-select it in the two Cognee nodes).
3. Workflow: `docker cp karyakarta_document_pipeline.n8n.json n8n:/tmp/kk_wf.json`,
   `docker exec n8n n8n import:workflow --input=/tmp/kk_wf.json`, `docker exec n8n n8n publish:workflow --id=OFViBfvIpWQltfiy`.
   (Or import from the UI and press **Publish**.)
4. Backend `.env`: `N8N_WEBHOOK_URL=http://localhost:5678/webhook/karyakarta-documents`
   (use `/webhook-test/...` only while the workflow is open in the editor and listening).

## Gotcha: publish after the node is loaded
n8n 2.x activates workflows through a publication outbox. If a version is published while n8n cannot load one of
its nodes (e.g. before the community node is installed), that publication is stored as **failed** and is not retried
for the same version. Fix: re-import (creates a new version) and publish again. Symptom: the webhook returns
404 "not registered" and the backend timeline shows "n8n unreachable → falling back to the in-process pipeline".

## If n8n is down
The backend runs the same steps in-process (`N8N_FALLBACK_INPROCESS=true`) using its own Cognee client, so uploads
never stall. The timeline shows which path ran ("Workflow started" vs "n8n unreachable").

## Voice chase workflow ("Karyakarta - Voice chase", id kkVoiceChase0001, 23 nodes)
Generated by `build_voice_workflow.py`. **Start:** `POST /webhook/karyakarta-voice-chase {case_id, to_number}`: get the agent context,
place the call through the backend (Sarvam Instant Outbound), wait 15 s and poll until it ends (up to 15 minutes), then record it.
A refused call becomes a *Voice call not placed* entry with Sarvam's reason. **Result:** `POST /webhook/karyakarta-voice-result` records an
already finished call. Both end in the same steps: record on the case, store in Cognee (native Remember node with a unique file name
prefix), refresh the graph. Import and publish like the document workflow; after an n8n restart the webhooks take about 20 seconds
to register.
