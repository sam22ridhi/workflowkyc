# Karyakarta backend

One FastAPI backend for the Karyakarta frontend: document upload, Sarvam Document Intelligence extraction,
deterministic cross-document checks, Cognee memory, and the n8n pipeline that ties them together.

**Principle:** the model reads (Sarvam), code checks (Python rules), the model explains (Cognee), a human approves.
All data in the demo is synthetic. The registry the checks compare against is a **mock** (`app/registry/mock_registry.py`).

```
React (Vite :5173) ──REST/SSE──> FastAPI (:8765) ──> SQLite (cases, documents, checks, audit) + storage/{case}/ (files)
                                     │   ▲
                         webhook     ▼   │ HTTP (extract, memory summary, report-back, cross-check)
                                   n8n (Docker :5678) ──native Cognee nodes──> Cognee Cloud (knowledge graph)
                                     │
                       backend only ─┴─> Sarvam Document Intelligence (extract + digitise)
```

The UI never depends on n8n or Cognee to render a case: the backend is the record of every status. If n8n is down,
the backend runs the same steps in-process; if Cognee is down, extraction, checks and the UI keep working and the
documents show `memory_status: failed`.

## 1. Setup (Windows)

Requires Python 3.11 (3.12 also works), Docker Desktop (for n8n) and Node 18+ (frontend).

```bat
cd workflowkyc\backend
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env        &REM then fill in SARVAM_API_KEY and COGNEE_API_KEY
```

### Environment variables (`backend/.env`; never commit it)

| Variable | Default | Meaning |
|---|---|---|
| `PORT` | `8765` | Backend port (8000 is blocked on the dev machine). `run.bat` uses 8765. |
| `CORS_ORIGINS` | `http://localhost:5173,…` | Frontend origins allowed to call the API. |
| `SARVAM_API_KEY` | | Sarvam subscription key. |
| `SARVAM_SUBMITS_PER_MINUTE` / `SARVAM_MAX_IN_FLIGHT` | `9` / `3` | Job-submission limiter (Sarvam allows 10/min). |
| `DEMO_MODE` | `false` | `true`: serve recorded Sarvam results and saved case answers from `demo_cache/` instead of calling out. |
| `N8N_WEBHOOK_URL` | `http://localhost:5678/webhook/karyakarta-documents` | Production webhook. Use `/webhook-test/…` only while the editor is listening. |
| `N8N_FALLBACK_INPROCESS` | `true` | If n8n is unreachable, run the pipeline in the backend. |
| `PIPELINE_AUTORUN` | `true` | `false`: uploads only store files (used by tests and the seed script). |
| `COGNEE_MODE` | `cloud` | `cloud` (HTTP) or `local` (python `cognee` library, see `requirements-local.txt`; not set up). |
| `COGNEE_BASE_URL`, `COGNEE_TENANT_ID`, `COGNEE_USER_ID` | tenant values | Cognee Cloud tenant. |
| `COGNEE_API_KEY` | | Cognee Cloud key. Also stored in the n8n credential *Cognee Cloud (Karyakarta)*. |
| `COGNEE_TIMEOUT_SECONDS` | `60` | Per-request timeout for Cognee calls. |
| `SARVAM_AGENT_ID`, `SARVAM_API_KEY_NEW_FOR_VOICE` | | Samvaad voice agent for Voice Chase. Needs an **agent** API key from the Sarvam console, not the Document Intelligence key. Setup: [`voice/SARVAM_AGENT_SETUP.md`](voice/SARVAM_AGENT_SETUP.md). |
| `SARVAM_ORG_ID`, `SARVAM_WORKSPACE_ID` | workspace values | Sarvam org / workspace for the agent. |
| `N8N_VOICE_WEBHOOK_URL` | | `http://localhost:5678/webhook/karyakarta-voice-chase`: n8n workflow that places the call. Empty: the timeline says "Voice call not placed". |

Frontend: `VITE_API_URL` (default `http://localhost:8765`) in `workflowkyc/.env.local` if the backend runs elsewhere.

## 2. Run order

1. **Backend**: `run.bat` (or `.venv\Scripts\python.exe -m uvicorn app.main:app --port 8765`). Docs at http://localhost:8765/docs.
2. **n8n**: Docker container `n8n` on port 5678 with the Cognee community node, the credential and the published
   workflow. One-time setup and the publish gotcha are in [`n8n/README.md`](n8n/README.md).
3. **Frontend**: `cd workflowkyc && npm install && npm run dev`, then open http://localhost:5173.

## 3. Demo data

```bat
seed.bat --reset                REM 5 cases; Sharma Foods has no documents yet (live upload demo)
seed.bat --reset --hero-docs    REM also process the 8 Sharma Foods documents from the cache (about 20 s, no Sarvam calls)
seed.bat --refresh-cache        REM live Sarvam + Cognee run; re-records demo_cache\ and the standard case answers (about 4 min)
```

- Hero case **Sharma Foods Private Limited** (`KYB-20814`): 8 synthetic PDFs in `seed/sharma_foods/` (watermarked
  "SPECIMEN - SYNTHETIC DEMO DATA", no emblems), regenerated byte-identically by `python -m seed.make_docs`.
  Planted issues the checks find: cheque name "Sharma Foods" ≠ legal name; signatory Ravish Sahay is not a director;
  Rakesh Sharma owns 18% through Sharma Holdings LLP with no KYC; GST says Navi Mumbai, application says Mumbai.
  Expected route: **ESCALATE**.
- The other four cases have no documents: they carry **precomputed** check results labelled "Seeded demo result", and
  their checklist shows the required documents as present (Royal Rajasthan Spices is seeded with one missing). Only
  Sharma Foods is read from real documents, so only it has evidence to open.

### Demo script
1. `seed.bat --reset`, start backend, n8n, frontend.
2. Merchant view → Upload → drop the 8 files from `backend/seed/sharma_foods/` in one go.
3. KAM view → Sharma Foods: statuses update live (SSE); about 2 minutes later the case is routed **ESCALATE** with 4 issues.
4. *Interactive PDF Evidence*: the real PDFs with Sarvam's fields; click a field or a box to cross-highlight.
5. *Auto-Filled CRM Form*: 100% filled with citations; two conflicts marked; "Edit Field" overrides are audited.
6. Ask the case: "Who owns more than 10% of Sharma Foods, directly or indirectly?" → Rakesh Sharma 18% (via the LLP).

**If the network fails on stage:** set `DEMO_MODE=true` in `.env`, restart the backend and re-upload. Extraction is
served from `demo_cache/` (same files, same hashes) and the standard questions have saved answers. Memory
shows `failed` but everything else works.

## 4. API (all under `/api`, JSON envelope `{ok, data}`)

| Endpoint | Purpose |
|---|---|
| `GET /cases` | KPIs + pipeline rows (stage, route, flags, doc progress, SLA) |
| `GET /cases/{id}` | Header, 8-stage tracker, checklist, checks, findings, summary, timeline |
| `POST /cases/{id}/documents` | Batch upload (multipart `files`, optional `slot`, `doc_types`); 202 with doc ids + SHA-256 |
| `GET /cases/{id}/documents`, `GET /documents/{id}`, `GET /documents/{id}/file` | Records, fields + boxes, original file (inline) |
| `POST /documents/{id}/extract` / `locate` / `status` / `type` | Extraction (n8n), evidence boxes, status from n8n, KAM type fix |
| `GET /documents/{id}/memory-summary`, `POST /documents/{id}/memory`, `POST /documents/{id}/memory/result` | Cognee: what to store, store via backend, report-back from n8n |
| `POST /cases/{id}/memory/cognify` / `graph-start` / `graph-result`, `GET /cases/{id}/memory` | Knowledge-graph build and status |
| `POST /cases/{id}/ask` | Case Q&A over Cognee (answer + source documents; 503 if unavailable) |
| `POST /cases/{id}/cross-check` | The 10 checks + AUTO/ASK/ESCALATE triage (returns `issues` for n8n) |
| `GET /cases/{id}/crm-form`, `POST /cases/{id}/crm-form/override` | Auto-filled CRM form with citations/conflicts; audited overrides |
| `POST /cases/{id}/action` | voice / request / approve / submit_to_compliance / send_back / compliance_approve. **Role and stage guarded**: the agent and merchant get 403 on decisions; Compliance acts only at stage 5 (after the KAM submits); approval needs finished verification |
| `GET /cases/{id}/events`, `GET /events` | Server-sent events (audit trail); `?after=<id>` to replay |
| `GET /mock-registry/{id}` | The MOCK MCA / GST / penny-drop record used by the checks |
| `GET /cases/{id}/voice-chase/context`, `POST /cases/{id}/voice-chase/result` | Voice agent variables + opening line (merchant-fixable items only); call outcome (stored as a call record, shown on the case) |
| `POST /cases/{id}/memory/items` | n8n reports the dataset's `{id, name}` items so answers can name their source documents |
| `GET /voice-calls/{id}/memory-summary`, `POST /voice-calls/{id}/memory/result` | Cognee: what n8n stores for a finished call; report-back |

## 5. How it works (short)
- **Extraction** (`app/extraction.py`, `app/sarvam/`): one schema per document type (8 types). `extract` gives values,
  confidence and page; Sarvam returns no coordinates there, so a `digitise` pass supplies layout blocks
  (`bbox_norm`, 0-1) and each value is matched to its block. Tables are boxed at table level (Sarvam has no cell
  coordinates); unmatched values get no box. Nothing is guessed.
- **Checks** (`app/checks/cross_check.py`): legal name, PAN type, GSTIN⊃PAN, CIN, signatory is director, beneficial
  owners >10% (look-through), bank holder + penny-drop, address drift, required documents, licence. Each has evidence
  (document, field, page, value) and an action: `ask` (merchant can fix) or `escalate` (human judgement).
- **Memory** (`app/memory_service.py`, `app/memory/`): one Cognee dataset per case (`case_<slug>`); per document a
  structured summary of fields and checks; cognify once per batch. Cognee answers questions; it never decides pass/fail.

## 6. Tests
Backend: `.venv\Scripts\python.exe -m pytest -q` (64 tests): validators, schemas, box location on real Sarvam fixtures,
cross-checks on the planted issues, CRM form, memory (fake store), Cognee outage, seeded-case coherence, and an
end-to-end integration test on the 8 real PDFs with recorded Sarvam responses and a fake Cognee.
Frontend: `cd workflowkyc && npm test` (21 render tests, jsdom): the dashboard, case overview, upload screen and live
hooks rendered against real backend responses captured in `src/test/fixtures/`. Re-capture them after changing the API
(start the backend after `seed.bat --reset --hero-docs`, then `curl` the endpoints listed in `src/test/ui.test.tsx`).
Neither suite calls Sarvam or Cognee. The PDF viewer (pdf.js) is not exercised in jsdom; check it in a browser.

## 7. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Timeline says "n8n unreachable → falling back to the in-process pipeline" | n8n down or workflow not published. `curl -X POST localhost:5678/webhook/karyakarta-documents` should not 404. See `n8n/README.md` (publish gotcha). |
| n8n webhook 404 "not registered" right after publishing | Version was published while a node type was unknown. Re-import the workflow and publish again. |
| n8n nodes can't reach the backend | Backend must listen on `0.0.0.0:8765`; n8n uses `http://host.docker.internal:8765` (Settings node). |
| Document `error`: "Sarvam rejected the file (HTTP 400)…" | Corrupt / unsupported file. PDF ≤ 10 pages, pdf/jpg/png ≤ 25 MB. |
| Extraction slow / queued | Sarvam allows 10 job submissions per minute; the limiter queues the rest. 8 documents take about 1 minute plus boxes. |
| `memory_status: failed` "rejected the credentials (401)" | Wrong `COGNEE_API_KEY` (backend `.env` and the n8n credential). Extraction and checks are unaffected. |
| Ask returns 503 | Cognee unreachable and no saved answer for that question. Use the standard questions with `DEMO_MODE=true`. |
| Fields shown but no highlight boxes | Boxes come from a second Sarvam pass (digitise) that runs after extraction; wait a few seconds. Table rows are highlighted at table level only. |
| `memory_status: failed` with "Your request is invalid" / HTTP 409 "DocumentUpdateRequiredError" | A file name was re-used with different content. Use the n8n workflows as shipped (Remember with unique prefixes); see `n8n/README.md`. |
| Graph status `none` | No document of the case was stored in Cognee yet (or all failed). |
| Voice probe: `Failed to get signed URL: 401` / "Invalid API key format" | `SARVAM_API_KEY_NEW_FOR_VOICE` is a standard Sarvam key. Create an agent API key in the console (see `voice/SARVAM_AGENT_SETUP.md` section 0). |
| Voice probe: 404 "App not found for the interaction type" | Wrong agent id, or the probe is in chat mode: the agent is call-only (the probe defaults to `--mode call`). |
| Server stops answering after a code change | Open browser tabs hold live-update streams; `run.bat` now limits shutdown to 2 s. If it still hangs, close the terminal and run `run.bat` again. |
| Port 8000 errors | Use 8765 (`run.bat`), and `VITE_API_URL` if you change it. |
| `UnicodeEncodeError` in a Windows console | Set `PYTHONIOENCODING=utf-8`; the seed script already does this for its own output. |
| Uploaded file type wrong (e.g. PAN vs GST) | Type comes from the filename, slot, or OCR keywords; fix with `POST /api/documents/{id}/type` and re-extract. |

The earlier PAN-only prototype (`workflowkyc/karyakarta-backend/`) is untouched and superseded by this backend.
